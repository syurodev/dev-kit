# Agent Hub Implementation Plan

> **READY FOR IMPLEMENTATION (revised 2026-08-12):** `internal/sandbox` is **on `main`** (PR #22 squash `c0267cf`, ADR-009). Do **not** spawn real vendor CLIs outside the sandbox. This revision incorporates research-backed wiring so Hub + ACP stdio work **through** sandbox, not around it.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Task 0 is mandatory** before Claude `Open()`.

**Goal:** Ship DevKit **Agent Hub** as a built-in module: multi-tab ACP client sessions (mock + Claude adapters), Capability Gateway–gated orchestration, SQLite session/turn storage, UI streaming, and MCP tools (`agenthub.*`) so one agent can invoke another — matching `/dev-kit/agent-hub`.

**Architecture:** `internal/acp` owns vendor-agnostic ACP v1 types + line-delimited JSON-RPC over an existing `io.ReadWriteCloser` (**no** dependency on `sandbox`). `internal/sandbox` owns OS isolation and (after Task 0) **piped** subprocess I/O. `internal/agenthub` owns `VendorAdapter` registry, session orchestration, depth/cycle guard, permission mediation (via `interaction.Hub` / UI — **no auto-approve**), SQLite persistence, and **wires** Claude spawn as `sandbox.StartPiped` → `acp.NewConn`. Bridge + MCP both call `AgentHubService` through `AppService.Call`. Frontend registers module `agenthub` with a multi-tab workbench view.

**Tech Stack:** Go 1.26 (`GOTOOLCHAIN=auto`), existing SQLite migrations (`internal/storage`), `interaction` hub, MCP `go-sdk`, React/Vite/bun frontend, `go-task`, `internal/sandbox` (bwrap / Seatbelt). **No** community ACP Go SDK — hand-roll transport + types (design NFR).

- Sandbox consumer contract: `/dev-kit/sandbox`, [ADR-009](https://github.com/syurodev/base/blob/main/content/projects/dev-kit/architecture-decisions.mdx) (OS-primitive sandbox)

## Research-backed revisions (why the old Hub plan was wrong)

These changes replace the POSTPONED “just call `sandbox.Start`” note with concrete wiring. Each bullet is grounded in shipped code or primary docs — not vibes.

### R1 — ACP needs bidirectional pipes; current `sandbox.Start` cannot host ACP

**Evidence:**
- ACP stdio transport ([official v1 transports](https://agentclientprotocol.com/protocol/v1/transports)): client launches agent; agent reads JSON-RPC from **stdin**, writes to **stdout**; messages are newline-delimited; stderr is logs only. Clients must keep both directions open for the session lifetime.
- Shipped `internal/sandbox` backends (`backend_bwrap.go`, `backend_seatbelt.go`) call `NewProcWithBuffers`, which assigns stdout/stderr to `bytes.Buffer` and **never** creates stdin/stdout pipes. `Proc.Stdin()` / `Stdout()` today expose the already-assigned `cmd.Stdin`/`Stdout` fields (not usable ACP pipes).

**Decision:** Add **Task 0** — `sandbox.Runner.StartPiped` (or equivalent IO mode) that:
1. Uses `cmd.StdinPipe()` + `cmd.StdoutPipe()` (stderr may stay buffered or piped for logging).
2. Still applies the same `Policy` → bwrap/Seatbelt recipe as `Start`.
3. Returns a `*Proc` (or thin wrapper) exposing `io.WriteCloser` stdin + `io.ReadCloser` stdout for `acp.NewConn`.

**Why not** “spawn unsandboxed in `acp.StartProcess` then hope Hub adds sandbox later”: that recreates the security hole Hub was postponed for. **Why not** “buffer Start + fake ACP”: violates the protocol and cannot stream `session/update`.

### R2 — Keep `acp` free of `sandbox`; Hub owns the wire-up

**Evidence:** Arch tests already treat leaf packages as directional (`internal/arch`). Sandbox docs call `internal/sandbox` a **leaf**. ACP design NFR separates transport from product orchestration.

**Decision:**
- `internal/acp`: codec + `Conn` over any `io.ReadWriteCloser` + shared cancel ladder helpers that take a `Killer`/`Waiter` interface (PID + Kill + Wait).
- `internal/agenthub` (Claude adapter): `sandbox.DefaultRunner().StartPiped(...)` → wrap pipes → `acp.NewConn`.
- `acp.StartProcess` (unsandboxed) is **test-only / mock helpers** — **forbidden** for real vendors in production paths.
- Arch bans: `acp → sandbox` **banned**; `agenthub → sandbox` **allowed**; `agenthub → mcp|bridge|app` banned as before.

### R3 — Claude v1 must use `NetworkHost` (default `NetworkNone` blocks the model API)

**Evidence:** `Policy` defaults `Network` to `NetworkNone` (`policy.go` `withDefaults`). Claude ACP bridge (`@agentclientprotocol/claude-agent-acp` / Claude Code) talks to Anthropic over HTTPS. With `NetworkNone`, bwrap adds network namespace isolation / Seatbelt denies network — the agent process cannot complete `initialize`/`session/prompt` against the API.

**Decision:** Claude adapter locks `Network: sandbox.NetworkHost` in v1. Document clearly that domain allowlisting is **sandbox v1.1+**, not Hub v1. Mock adapter: **no** sandbox, **no** network requirement.

### R4 — Private home tmpfs + `npx -y` is a footgun; prefer a real binary + explicit env

**Evidence:**
- Sandbox `EffectivePrivateHome()` defaults **true** — host `$HOME` is hidden; a fresh tmpfs home is injected. That breaks npm/npx caches, global `npx` downloads into `~/.npm`, and Claude config under `~/.claude` unless explicitly remounted.
- Reference clients spawn `npx -y @agentclientprotocol/claude-agent-acp` on the **host** (full home + network). Inside a private-home jail that pattern is unreliable without RO binds for Node, the package store, and writable cache dirs.

**Decision (Claude v1 spawn policy):**
1. **Prefer** configured absolute binary / `claude-agent-acp` on `PATH` resolved **before** jail, then exec that path inside the sandbox (`Cmd.Path` must be absolute and readable via `ReadOnlyPaths` as needed).
2. `npx -y …` is **fallback only** when explicitly enabled (`ClaudeOptions.AllowNpx`); requires extra RO binds (node, npm prefix) + RW cache dir under `WorkDir` or a dedicated sandbox cache path — spike in Task 0/11, fail with clear `agenthub.processFailed` if unresolved.
3. Pass env allowlist into `Policy.Env` (at least `ANTHROPIC_API_KEY` / `CLAUDE_API_KEY` as used by the bridge — **never log values**). Do not inherit full host env into the jail.
4. Mount project `WorkDir` RW (already default); add RO binds for the agent binary and node runtime as discovered by the adapter.

### R5 — Cancel must target the sandbox supervisor PID; rely on existing bwrap recipe

**Evidence:**
- Linux recipe already passes `--unshare-pid` and `--die-with-parent` (`bwrap_args.go`). The Go `exec.Cmd` PID is the **bwrap** supervisor, not necessarily the innermost agent PID.
- Community reports: `--die-with-parent` alone can miss grandchildren without a PID namespace; with `--unshare-pid`, killing bwrap tears down the nested PID namespace.

**Decision:** Cancel ladder signals/kills **`sandbox.Proc.PID()`** (outer supervisor). Order unchanged: ACP `session/cancel` → wait 5s → SIGTERM → wait 5s → SIGKILL. Do **not** try to discover inner PIDs in v1. Seatbelt path: same — kill the `sandbox-exec` process group leader returned by `Proc`.

### R6 — Fail closed when sandbox backend missing; mock stays in-process

**Evidence:** ADR-009 + `/dev-kit/sandbox`: Hub must fail closed if backend unavailable. `DefaultRunner` on unsupported platforms / missing `bwrap` returns errors from Start.

**Decision:**
- **mock** adapter: in-process loopback, **does not** call sandbox (needed for CI/headless hello-world).
- **claude** (and future real vendors): if `StartPiped` returns unavailable/invalid → surface `agenthub.processFailed` / dedicated `agenthub.sandboxUnavailable`; **never** fall back to unsandboxed `exec`.
- UI: show sandbox backend status (linux/bwrap | darwin/seatbelt | unavailable) on create-session failure.

### R7 — Docs examples that say `Start(...)` for Hub are incomplete until Task 0

Base `/dev-kit/sandbox` still shows `DefaultRunner().Start` as the Hub entrypoint. That API is correct for fire-and-capture helpers, **not** for ACP. After Task 0 ships, update base sandbox page + any Hub callouts to prefer `StartPiped` for ACP vendors (Task 15).

```go
package acp

import (
	"bufio"
	"encoding/json"
	"fmt"
	"io"
)

type Request struct {
	JSONRPC string          `json:"jsonrpc"`
	ID      any             `json:"id"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params,omitempty"`
}

type Response struct {
	JSONRPC string          `json:"jsonrpc"`
	ID      any             `json:"id"`
	Result  json.RawMessage `json:"result,omitempty"`
	Error   *RPCError       `json:"error,omitempty"`
}

type Notification struct {
	JSONRPC string          `json:"jsonrpc"`
	Method  string          `json:"method"`
	Params  json.RawMessage `json:"params,omitempty"`
}

type RPCError struct {
	Code    int             `json:"code"`
	Message string          `json:"message"`
	Data    json.RawMessage `json:"data,omitempty"`
}

// Message is a decoded inbound line (request, response, or notification).
type Message struct {
	JSONRPC string          `json:"jsonrpc"`
	ID      json.RawMessage `json:"id"` // null/absent for notifications; present for req/resp
	Method  string          `json:"method,omitempty"`
	Params  json.RawMessage `json:"params,omitempty"`
	Result  json.RawMessage `json:"result,omitempty"`
	Error   *RPCError       `json:"error,omitempty"`
}

func WriteMessage(w io.Writer, v any) error {
	b, err := json.Marshal(v)
	if err != nil {
		return err
	}
	_, err = w.Write(append(b, '\n'))
	return err
}

func ReadMessage(r io.Reader) (Message, error) {
	br, ok := r.(*bufio.Reader)
	if !ok {
		br = bufio.NewReader(r)
	}
	line, err := br.ReadBytes('\n')
	if err != nil {
		return Message{}, err
	}
	var m Message
	if err := json.Unmarshal(bytesTrimSpace(line), &m); err != nil {
		return Message{}, fmt.Errorf("acp: decode: %w", err)
	}
	if m.JSONRPC != "2.0" {
		return Message{}, fmt.Errorf("acp: bad jsonrpc %q", m.JSONRPC)
	}
	return m, nil
}

func bytesTrimSpace(b []byte) []byte { /* trim \r\n space */ }
```

Adjust `ID` typing as needed so responses correlate (use `json.Number` / `float64` / string consistently — document choice in comment: prefer unmarshaling id into `any` via intermediate map if tests need it).

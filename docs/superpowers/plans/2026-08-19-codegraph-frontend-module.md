# CodeGraph Frontend Module (Phase 1c: minimal UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register CodeGraph as a real Dock module with a minimal UI (FR-7: folder picker, "Re-index" button, endpoint list, click-to-view flow as text/tree) — the last missing piece of Phase 1. This is the first thing in the whole CodeGraph effort that calls `CodeGraphOpenProject`/`ListEndpoints`/`GetApiFlow`/`SearchSymbol` (built in `2026-08-18-codegraph-core-go.md`) with a real, user-chosen project path instead of a test fixture.

**Architecture:** Standard module shape already established by every other built-in module (`ssh`, `database`, ...): a hand-written bridge wrapper (`frontend/src/bridge/codegraph.ts`) around the Wails-generated bindings, a `ModuleManifest` (`frontend/src/modules/codegraph/manifest.ts`), a single view component (`CodeGraphView.tsx`) registered in `Workbench.tsx`. Folder selection uses `Dialogs.OpenFile({CanChooseDirectories: true, CanChooseFiles: false})` from `@wailsio/runtime` — the first module in this codebase to need a native folder picker (verified against the package's real `.d.ts`, not assumed). No `SetProjectPath` call is added here: it stays exactly where Phase 1a left it, inside `CodeGraphService`'s own construction in `container.go` — wiring a *specific chosen folder* into `SetProjectPath` is Go-side plumbing that belongs to whichever plan makes `OpenProject` actually derive a real per-project SQLite path from the chosen folder (a small gap Phase 1a explicitly deferred); this plan's `CodeGraphOpenProject(path)` bridge call already exists end-to-end and works once that plumbing lands — calling it before then will surface `ErrNoActiveProject` cleanly (already-tested Go behavior), not crash.

**Tech Stack:** React, TypeScript, `@wailsio/runtime` (`Dialogs`), Wails-generated bindings (`task generate:bindings`). **No unit tests** — this repo's frontend has zero unit test infrastructure (`AGENTS.md`: the frontend check is `cd frontend && bun run build`, i.e. `tsc` + `vite build`, not `vitest`/`jest`). Per the same precedent already established in this repo's own `docs/superpowers/plans/2026-08-15-workbench-tab-strip.md` ("Tech Stack deviation from the skill default"), each task below verifies with a typecheck/build step, and the final task is a concrete manual QA script exercising the actual branchy bits (empty project, unresolved-analyzer error, re-index).

**Explicit scope boundary:** No Graph UI canvas (that's `2026-08-19-codegraph-graph-ui.md`-equivalent, a later phase — this ships the FR-7 "list/tree/text" UI only). No file editing, no terminal, no plan-first flow. No search-symbol UI wired in this pass either (`SearchSymbol` bridge method already exists but this task's endpoint-list-first UI doesn't need it yet — add a search box in a later pass if the flat endpoint list proves too long to scan, YAGNI for now).

## Task 2: Bridge wrapper

**Files:**
- Create: `frontend/src/bridge/codegraph.ts`

- [ ] **Step 1: Confirm the exact generated method/type names to wrap**

Before writing this file, read whatever `frontend/bindings/devkit/internal/bridge/*.ts` file Task 1 confirmed contains the `CodeGraph*` methods, and read `frontend/src/bridge/ssh.ts` in full for the wrapping convention this repo already uses (`callBridge()` from `./client`, one exported async function per bridge method, one exported type per Go struct). Match that convention exactly — do not invent a different pattern for this one module.

- [ ] **Step 2: Write the wrapper**

Adjust the import path/method names below to whatever Task 1 Step 2 actually found generated (this is written against the *expected* shape given the Go signatures already built in Phase 1a — `CodeGraphOpenProject(path string) error`, `CodeGraphListEndpoints() ([]codegraph.Endpoint, error)`, `CodeGraphGetApiFlow(endpointID string) (codegraph.ApiFlow, error)`, `CodeGraphSearchSymbol(query string) ([]codegraph.SymbolMatch, error)` — the generated TS signatures should mirror these 1:1):

```typescript
// frontend/src/bridge/codegraph.ts
import { callBridge } from "./client";
import { AppService } from "../../bindings/devkit/internal/bridge";

export type CodeGraphEndpoint = {
  id: string;
  httpMethod: string;
  path: string;
  entryNode: string;
};

export type CodeGraphFlowStep = {
  label: string;
  filePath: string;
  line: number;
};

export type CodeGraphApiFlow = {
  endpointId: string;
  steps: CodeGraphFlowStep[];
};

export type CodeGraphSymbolMatch = {
  nodeId: string;
  label: string;
  kind: string;
  filePath: string;
  line: number;
};

export async function openCodeGraphProject(path: string): Promise<void> {
  return callBridge(() => AppService.CodeGraphOpenProject(path));
}

export async function listCodeGraphEndpoints(): Promise<CodeGraphEndpoint[]> {
  return callBridge(() => AppService.CodeGraphListEndpoints());
}

export async function getCodeGraphApiFlow(endpointId: string): Promise<CodeGraphApiFlow> {
  return callBridge(() => AppService.CodeGraphGetApiFlow(endpointId));
}

export async function searchCodeGraphSymbol(query: string): Promise<CodeGraphSymbolMatch[]> {
  return callBridge(() => AppService.CodeGraphSearchSymbol(query));
}
```

Note this wrapper is simpler than `bridge/ssh.ts`'s — SSH's `toProfile()` mapping function exists specifically to convert Go's snake_case JSON (`auth_method`) into camelCase TS (`authMethod`); CodeGraph's Go structs already use camelCase JSON tags (a deliberate choice made when those tags were added in the Java analyzer plan, precisely to avoid needing this conversion step), so there's no mapping function here — the generated types can be used close to as-is. If Task 1's generated types already match these shapes exactly (likely, since Wails typically names generated interfaces after the Go type), the local type aliases above are still worth keeping (matches this repo's convention of not importing generated-binding types directly into view components — see how `SSHView.tsx` imports `SSHProfile` from `../../bridge/ssh`, never from `bindings/`), but simplify to `export type CodeGraphEndpoint = AppService.Endpoint` (or whatever the generated name is) instead of hand-duplicating fields if that turns out cleaner once you see the real generated shape.

## Task 4: `CodeGraphView` — folder picker, re-index, endpoint list, flow view

**Files:**
- Create: `frontend/src/modules/codegraph/CodeGraphView.tsx`

- [ ] **Step 1: Write the view**

```tsx
// frontend/src/modules/codegraph/CodeGraphView.tsx
import { useState } from "react";
import { Dialogs } from "@wailsio/runtime";
import {
  openCodeGraphProject,
  listCodeGraphEndpoints,
  getCodeGraphApiFlow,
  type CodeGraphEndpoint,
  type CodeGraphApiFlow,
} from "../../bridge/codegraph";
import { errorMessage } from "../../bridge/errors";

export function CodeGraphView() {
  const [projectPath, setProjectPath] = useState("");
  const [endpoints, setEndpoints] = useState<CodeGraphEndpoint[]>([]);
  const [selectedFlow, setSelectedFlow] = useState<CodeGraphApiFlow | null>(null);
  const [status, setStatus] = useState("");
  const [error, setError] = useState("");
  const [busy, setBusy] = useState(false);

  async function pickAndOpenProject() {
    setError("");
    let chosen: string;
    try {
      chosen = (await Dialogs.OpenFile({
        CanChooseDirectories: true,
        CanChooseFiles: false,
        Title: "Open Java project",
      })) as string;
    } catch (e) {
      setError(errorMessage(e));
      return;
    }
    if (!chosen) {
      return; // user cancelled the picker
    }
    setProjectPath(chosen);
    await reindex(chosen);
  }

  async function reindex(path: string) {
    setBusy(true);
    setStatus("Indexing…");
    setError("");
    setSelectedFlow(null);
    try {
      await openCodeGraphProject(path);
      const list = await listCodeGraphEndpoints();
      setEndpoints(list);
      setStatus(`Indexed. ${list.length} endpoint(s) found.`);
    } catch (e) {
      setEndpoints([]);
      setStatus("");
      setError(errorMessage(e));
    } finally {
      setBusy(false);
    }
  }

  async function viewFlow(endpoint: CodeGraphEndpoint) {
    setError("");
    try {
      const flow = await getCodeGraphApiFlow(endpoint.id);
      setSelectedFlow(flow);
    } catch (e) {
      setSelectedFlow(null);
      setError(errorMessage(e));
    }
  }

  return (
    <div className="flex h-full flex-col gap-4 p-4">
      <div className="flex items-center gap-2">
        <button onClick={pickAndOpenProject} disabled={busy}>
          Open Java project…
        </button>
        {projectPath && (
          <button onClick={() => reindex(projectPath)} disabled={busy}>
            Re-index
          </button>
        )}
        {projectPath && <span className="text-sm text-muted-foreground">{projectPath}</span>}
      </div>

      {status && <p className="text-sm">{status}</p>}
      {error && <p className="text-sm text-destructive">{error}</p>}

      <div className="flex flex-1 gap-4 overflow-hidden">
        <ul className="w-1/3 overflow-y-auto border-r pr-2">
          {endpoints.map((ep) => (
            <li key={ep.id}>
              <button className="w-full text-left" onClick={() => viewFlow(ep)}>
                <span className="font-mono text-xs">{ep.httpMethod}</span> {ep.path}
              </button>
            </li>
          ))}
          {endpoints.length === 0 && !busy && (
            <li className="text-sm text-muted-foreground">No endpoints yet — open a project to index it.</li>
          )}
        </ul>

        <div className="flex-1 overflow-y-auto">
          {selectedFlow ? (
            <ol className="list-decimal pl-4">
              {selectedFlow.steps.map((step, i) => (
                <li key={i} className="font-mono text-sm">
                  {step.label} <span className="text-muted-foreground">({step.filePath}:{step.line})</span>
                </li>
              ))}
            </ol>
          ) : (
            <p className="text-sm text-muted-foreground">Select an endpoint to see its flow.</p>
          )}
        </div>
      </div>
    </div>
  );
}
```

`errorMessage` is already imported by `SSHView.tsx` from `../../bridge/errors` (confirmed real, same import path) — reused here rather than hand-rolling error-to-string logic again.

## What this plan does NOT unlock yet

The folder the user picks isn't yet wired to a *persistent* per-project SQLite path via `SetProjectPath` with real project-key derivation (hashing the path, choosing a real data directory under the OS's app-support location) — `CodeGraphOpenProject` today still runs against whatever store `internal/app/container.go` constructed at startup (`codegraph.NewNilStore()`, per Phase 1a), so every `OpenProject` call in this UI will currently fail with a clean `ErrNoActiveProject`-derived error until that small remaining piece of Go plumbing lands (a good, contained next task on its own — deriving `filepath.Join(appDataDir, "codegraph", sha256(projectPath)+".db")` and calling `Service.SetProjectPath` with it before `OpenProject`, likely inside `CodeGraphOpenProject`'s bridge method itself). This plan's QA script (Task 6, Step 3) exists specifically because that gap is still open — the error path is the expected, correct behavior right now, not something this plan broke.

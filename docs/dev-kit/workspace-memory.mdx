# Workspace memory

Memory lưu trong DevKit để Claude, Codex và các session con dùng cùng kiến thức
của workspace. Dữ liệu gắn với `workspace.id`; đổi primary hoặc `cwd` không chuyển
memory. Hai workspace chứa cùng project có memory riêng.

Memory là dữ liệu tham khảo. Quy tắc làm việc nằm trong **Instructions** của
workspace; memory không cấp quyền và không thay thế yêu cầu của người dùng.
Prompt DevKit hướng dẫn agent lưu kiến thức lâu dài vào shared memory, tránh lưu
kiến thức workspace vào memory riêng của vendor.

## Dữ liệu và phiên bản

Mỗi mục có `kind`, `title`, `summary`, `body`, revision và nguồn cập nhật:

| Kind | Nội dung |
| --- | --- |
| `decision` | Quyết định kiến trúc và lý do |
| `convention` | Quy ước dự án |
| `knowledge` | Kiến thức về cách hệ thống hoạt động |
| `handoff` | Ghi chú bàn giao giữa session |

Title tối đa 256 byte, summary 1024 byte, body 32 KiB UTF-8; cả ba phải có nội dung.
Summary ngắn, nêu sự kiện; body chứa chi tiết và dẫn chứng. Không lưu credential
hoặc toàn bộ transcript vào memory.

Migration 35 thêm `workspace_memory` và `workspace_memory_revisions`. Memory lưu
local trong SQLite, ở dạng plaintext như workspace instructions, ngoài vault và
sync. Xóa workspace xóa memory và lịch sử của nó. Xóa một mục memory là soft delete:
`get` vẫn trả mục có `deleted: true`, còn list/search/context bỏ nó.

Create bắt đầu từ revision 1. Update, delete và restore bắt buộc `expectedRevision`
từ lần đọc hiện tại. Nếu session khác đã sửa, thao tác trả `memory.revisionConflict`;
agent đọc lại và hòa giải nội dung trước khi thử lại. Mỗi lần ghi cập nhật mục hiện
tại và thêm snapshot lịch sử trong cùng transaction. Restore sao chép một revision
còn sống thành revision mới, không sửa lịch sử cũ; không thể chọn tombstone làm
revision đích.

Nguồn cập nhật do host xác định: nhãn caller, session ID và loại agent. Tool input
không có trường để agent tự nhận mình là người dùng hoặc vendor khác. Audit chỉ ghi
action, workspace/entry ID và revision, không ghi query hay nội dung memory.

## Tool MCP

| Tool | Hành động |
| --- | --- |
| `workspace.memory.list` | Danh sách metadata và summary, bỏ body |
| `workspace.memory.search` | Tìm các từ/tiền tố trong title, summary hoặc body; trả summary |
| `workspace.memory.get` | Đọc toàn bộ mục cùng revision, kể cả mục đã soft delete |
| `workspace.memory.create` | Thêm mục mới; trả id/kind/title/summary/revision/updatedAt, không kèm body trừ khi `includeBody: true` |
| `workspace.memory.update` | Thay nội dung với expectedRevision; trả như `create` |
| `workspace.memory.delete` | Soft delete với expectedRevision; trả mục không kèm body |
| `workspace.memory.history` | Đọc các phiên bản (revision, operation, title, summary, updatedAt); body chỉ khi `includeBody: true` |
| `workspace.memory.restore` | Khôi phục targetRevision thành revision mới |

Agent Hub luôn lấy workspace ID đã lưu của session. `workspaceId` khác workspace
của session bị từ chối, và session không gắn workspace không dùng được memory.
Terminal CLI phải truyền `workspaceId` rõ ràng; host không suy workspace từ cwd.
Caller thiếu identity hoặc identity không hợp lệ bị từ chối. Các thao tác đi qua
capability `workspace-memory:read` / `workspace-memory:write`.

List/search dùng limit (mặc định 20, tối đa 100), trả `hasMore` và `nextCursor`.
Truyền `cursor` của trang trước để lấy trang tiếp theo. Cursor gắn với workspace,
query, kind và trạng thái deleted; đổi bộ lọc phải bắt đầu lại. Offset vẫn được hỗ
trợ để tương thích, nhưng không được kết hợp với cursor. MCP history dùng limit/offset
và chỉ trả metadata (thêm `includeBody` để lấy body); UI dùng cursor và metadata lịch sử riêng, chỉ tải snapshot khi mở.
Thứ tự danh sách là `updatedAt` giảm dần rồi ID giảm dần; lịch sử theo revision giảm dần.
Dữ liệu thay đổi giữa hai trang có thể làm kết quả thay đổi; Refresh đọc lại từ đầu.

## Tìm kiếm và hiệu năng

Migration 36 backfill chỉ mục SQLite FTS5 và read model summary cho dữ liệu hiện có.
Trigger cập nhật chỉ mục trong cùng transaction khi thêm, sửa, khôi phục hoặc xóa
workspace. Tìm kiếm được giới hạn bằng workspace ID cả trong chỉ mục lẫn bảng dữ liệu.
Không lập chỉ mục các phiên bản lịch sử.

Search tìm **từ hoặc tiền tố của từ**, không tìm chuỗi con ở giữa từ. Nhiều từ dùng
AND: `quy uoc` tìm mục chứa cả hai tiền tố, có thể nằm ở các trường khác nhau. Không
phân biệt hoa/thường và dấu Unicode Latin, nên `kien truc` tìm được `kiến trúc`.
Dấu câu phân tách từ; query không chứa từ trả danh sách rỗng. Query được chuyển thành
biểu thức literal an toàn, không nhận cú pháp FTS, wildcard `%` hay `_`. Đây là thay
đổi ngữ nghĩa so với search substring trước đó.

Danh sách, context và lịch sử UI đọc summary đã lưu sẵn, không tải hoặc parse body.
Phân trang cursor dùng index theo workspace và thứ tự cập nhật, tránh bỏ qua hàng
nghìn mục như offset. UI giữ một trang 20 mục, debounce search 200 ms và hủy request
đọc cũ khi bộ lọc hoặc lựa chọn thay đổi. Query rất rộng vẫn tốn chi phí theo số kết
quả khớp trong chỉ mục; giới hạn trang không làm mọi query có chi phí hằng số.

Có benchmark `BenchmarkMemory50K` với 50.000 mục body khoảng 1 KiB và 50.000 revision,
bao gồm search hiếm/phổ biến, cursor trang sâu và lịch sử. Chạy bằng:

```bash
go test ./internal/workspacememory/ -run '^$' -bench BenchmarkMemory50K -benchtime=1s -benchmem
```

## Quản lý trong giao diện

Mở menu workspace → **Workspace memory…**. Cửa sổ gắn với workspace đã chọn khi mở,
cho phép tìm kiếm, lọc kind, xem Active/Deleted, thêm và sửa memory. Xóa là soft delete.
History hiển thị nguồn cập nhật và revision; chọn một phiên bản để đọc nội dung rồi
Restore thành revision mới. Xóa và restore đều có xác nhận.

Nếu revision đã thay đổi, bản nháp được giữ lại và UI yêu cầu Reload latest trước
khi lưu lại. Chuyển mục hoặc đóng cửa sổ khi có thay đổi chưa lưu sẽ hỏi xác nhận.
Bridge quản lý dùng identity UI do host đặt, không nhận source từ frontend và từ chối
caller agent/terminal. Agent tiếp tục dùng tool MCP có workspace scope của session.

## Context của mỗi lượt

Agent Hub đọc snapshot trước mỗi lượt và đưa vào phần dữ liệu memory, sau
Instructions và trước session brief. Snapshot JSON tối đa 8 KiB, gồm ID, kind,
title, summary và revision của các mục cập nhật gần nhất; không chứa body. `omitted`
cho biết có mục chưa đưa vào; agent dùng search/get để lấy thêm chi tiết. Snapshot
mới thay snapshot cũ. Xóa mục hoặc xóa workspace có hiệu lực ở lượt tiếp theo.

Claude và Codex nhận cùng snapshot; echo người dùng và attachments giữ nguyên.
Lỗi đọc memory từ chối lượt trước khi ghi echo hoặc gọi vendor. Snapshot không ghi
vào transcript như một tin nhắn người dùng.

Protocol fixtures kiểm tra adapter và shared context; chúng chưa thay thế kiểm
chứng một phiên vendor thật trên desktop.

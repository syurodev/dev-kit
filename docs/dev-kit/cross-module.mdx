# Liên module

Các module của DevKit được thiết kế riêng lẻ, nhưng người dùng làm việc **xuyên
qua** chúng: đọc flow `POST /refunds` trong [Code Graph](/dev-kit/codegraph),
gọi thử nó trong [API Client](/dev-kit/api-client), nhờ agent trong
[Agent Hub](/dev-kit/agent-hub) sửa, commit việc đó trong
[Git](/dev-kit/git), theo dõi trong [Tasks](/dev-kit/tasks). Trang này định
nghĩa **hai primitive** để các bước đó liền mạch mà không module nào phải
import ruột của module khác.

## Nguyên tắc

1. **Tham chiếu, không sao chép.** Module A không lưu bản sao dữ liệu của
   module B; nó lưu một `EntityRef` và hỏi B khi cần hiển thị. Đây là luật
   Tasks ↔ Code Graph đã chốt (hai ID trỏ nhau, không FK, không copy status) —
   áp dụng cho mọi cặp.
2. **Ai sở hữu fact thì chỉ người đó ghi.** Code Graph sở hữu "code có tồn
   tại / có khớp plan", Tasks sở hữu "việc đang ở bước nào", API Client sở hữu
   "request gửi đi và response", Git sở hữu "cái gì đã đổi và đã commit chưa",
   Tài khoản sở hữu "tôi là ai trên dịch vụ này". Cần thêm dữ liệu thì thêm vào
   bên sở hữu.
3. **Ở lại module đang đứng khi có thể.** Hỏi agent mở **rail** trên module
   hiện tại thay vì chuyển sang Agent Hub; tạo task mở **peek** thay vì rời
   Code Graph. Chỉ chuyển tab khi đích là một công cụ làm việc (API Client).
4. **Một cửa cho agent.** Mọi thứ người làm được bằng chip/menu, agent làm
   được bằng MCP tool của module sở hữu, qua cùng Capability Gateway và cùng
   gate env — không có đường tắt vì "đây là agent gọi từ module khác".
5. **Credential đi theo ID, không đi theo giá trị.** Module tham chiếu một
   account bằng `account_id`; giá trị chỉ được giải trong Go ngay trước khi
   dùng. Hệ quả: không có tool MCP nào — của bất kỳ module nào — trả về một
   credential, và xoay vòng token không phải sửa module nào. Xem
   [Tài khoản](/dev-kit/accounts).

## Primitive 1 — `EntityRef`

Một giá trị nhỏ, serialize được, mô tả "cái đó ở module nào":

```ts
type EntityRef = {
  module: "codegraph" | "tasks" | "apiclient" | "agenthub" | "git" | "accounts" | "notes" | "database";
  kind: string;      // "endpoint" | "planNode" | "node" | "file" | "task" | "request" | "session" | "commit" | "diff" | "account" | …
  id: string;        // ID ổn định do module sở hữu cấp
  label: string;     // hiển thị khi module sở hữu chưa trả lời (offline, chưa index)
  project?: string;  // root project khi thực thể thuộc về một project
};
```

Dạng chuỗi (để dán, để agent đọc): `devkit://codegraph/endpoint/POST%20%2Frefunds?project=…`.

- Mỗi module đăng ký **resolver** cho `kind` của mình: `ref → {title, meta,
  status, open()}`. Chip hiển thị gọi resolver; resolver trả `stale` khi thực
  thể biến mất (endpoint bị xoá sau re-index) — chip vẫn hiện, gạch mờ.
- UI dùng một component duy nhất: **`Shared / Entity Chip`** (Figma), biến thể
  theo `kind`. Cùng chip xuất hiện trong composer của agent, header request của
  API Client, dòng plan của Code Graph, description của task.
- Kéo-thả chip giữa module là thao tác hợp lệ: thả chip endpoint vào composer
  = attach; thả vào task description = link.

Agent nhận `EntityRef` như **context có cấu trúc**, không phải text dán vào:
chip endpoint trong composer trở thành một attachment mà agent resolve qua
`codegraph.getApiFlow` — agent đọc flow mới nhất, không phải bản chụp lúc gửi.

## Primitive 2 — Intent

Module không import view của nhau; nó **dispatch intent**, module đích đăng ký
handler:

```ts
registerIntent("api.fromEndpoint", (ref: EntityRef) => …);   // apiclient
registerIntent("agent.attach", (refs: EntityRef[], prompt?: string) => …); // agenthub
registerIntent("task.create", (seed: { title: string; refs: EntityRef[] }) => …); // tasks
registerIntent("codegraph.reveal", (ref: EntityRef) => …);    // codegraph
registerIntent("git.reveal", (ref: EntityRef) => …);          // git — diff của file / commit
registerIntent("git.commitTurn", (ref: EntityRef) => …);      // git — checkpoint một lượt → commit
registerIntent("accounts.pick", (need: { host?: string; env?: string }) => …); // accounts — peek, không đổi tab

dispatchIntent("api.fromEndpoint", ref, { placement: "beside" });
```

`placement` quyết định document đích mở ở đâu: `"replace"` (group đang focus)
hoặc `"beside"` (document group bên cạnh — xem
[Layout § Document group](/dev-kit/layout#document-group--nhiều-document-cạnh-nhau)).
Mặc định do intent khai: *Try in API Client* mở `beside` để flow và response
cùng hiện; *Reveal in Code Graph* từ một task mở `replace`.

- Registry sống ở `frontend/src/workbench/intents.ts`, cạnh `openTab`. Module
  chưa cài / chưa bật ⇒ `dispatchIntent` trả `unavailable`, menu ẩn mục đó.
- Intent là **điều hướng UI**. Mọi ghi dữ liệu mà intent dẫn tới vẫn đi qua
  bridge của module đích → Capability Gateway. Intent không mang quyền.
- Thay dần các import chéo hiện có (`openFileInProject` từ AgentCompanion) và
  hai window event lẻ bằng intent tương ứng.

## Ma trận điểm nối

| Từ → Tới | Điểm chạm trong UI | Intent / tool | Ai sở hữu dữ liệu |
|---|---|---|---|
| Code Graph → API Client | Hover/menu endpoint: **Try in API Client** (`⌘↵`) | `api.fromEndpoint` | API Client tạo nháp; Code Graph chỉ cung cấp endpoint + param |
| Code Graph → Agent Hub | **Ask agent about this flow** (`⌘L`); banner lỗi index: **Ask agent** | `agent.attach([endpoint, planNode…])` | Agent Hub (session); Code Graph trả flow khi agent gọi tool |
| Code Graph → Tasks | **New task from endpoint** (`⌘T`); plan đã duyệt: **Create tasks from plan** | `task.create`, `tasks.createFromPlan` | Tasks; link hai chiều `plan_node_id` ↔ `task_id` |
| Tasks → Code Graph | Chip plan node / endpoint trong task detail | `codegraph.reveal` | Chỉ điều hướng |
| API Client → Code Graph | Chip nguồn trên request: **View flow** | `codegraph.reveal` | Chỉ điều hướng |
| API Client → Agent Hub | Response: **Attach to agent** | `agent.attach([request])` | Agent Hub; response đã cắt + che secret |
| API Client → Tasks | Response: **Add to task** | `tasks.comment.add` với ref request | Tasks (comment) |
| Agent Hub → Git | Bất kỳ lượt nào: **Commit lượt này** | `git.commitTurn` | Git sở hữu commit; Agent Hub chỉ cung cấp tập file của lượt |
| Git → Agent Hub | Diff / commit: **Attach to agent** | `agent.attach([commit \| diff])` | Agent Hub; diff đã cắt theo giới hạn |
| Git → Code Graph | Dòng commit: **Blast radius**; checkout branch ⇒ re-index | `codegraph.reveal`, `codegraph.reindex` | Code Graph trả phạm vi ảnh hưởng; Git chỉ nói file nào đổi |
| Code Graph → Git | Marker `M`/`A` ở tab Files; tab file: **View diff** | `git.reveal` | **Git sở hữu trạng thái git**; `codegraph.GitStatus` chuyển sang đọc từ Git |
| Tasks → Git | Task detail: commit mang `key`, nút tạo branch; cửa duyệt đóng task hỏi trạng thái commit/push | `git.reveal`, `git.branch.create` | **Git sở hữu**; Tasks hỏi lúc hiển thị, không lưu SHA |
| Git → Tasks | `git.commitTurn` seed trailer `Task: <key>` khi phiên đang giữ task | — | Liên kết nằm trong message commit, không nằm trong bảng nào của DevKit |
| API Client / Git → Accounts | Thiếu account hoặc account hết hạn: peek ngay tại chỗ | `accounts.pick` | Accounts; bên gọi chỉ nhận lại `account_id` |
| Accounts → mọi module | Account detail liệt kê ai đang dùng nó | usage index (như `ProfileEnvUsage`) | Module sở hữu binding trả lời |
| Agent Hub → mọi module | Agent tự gọi `codegraph.*`, `tasks.*`, `api.*`, `git.*`, `accounts.*` qua MCP | tool của module sở hữu | Module sở hữu, qua Gateway + gate env |
| Mọi module → Agent Hub | Rail companion mở trên module hiện tại; permission hiện trong rail/toast | — | Agent Hub |

## Code Graph là trạm trung tâm

Code Graph biết cấu trúc code nên là nơi phát ra nhiều ref nhất. Sidebar mới
([Figma · CodeGraph / Sidebar](https://www.figma.com/design/3dOzSZBYY7QtzANFTCfEe8/DevKit?node-id=1189-41340))
đặt các điểm chạm như sau:

- **Dòng endpoint**: hover hiện ba nút (Try, Ask agent, More); `More` mở menu
  đầy đủ (Try in API Client, Ask agent, New task, Copy as cURL, Reveal handler).
- **Tab Plan**: badge đếm node lệch; plan đã duyệt hiện chip task trên từng
  dòng và nút *Create tasks from plan*.
- **Tab Files**: marker thay đổi (`M`/`A`); *blast radius* của file nằm ở
  panel *Impact* dưới editor của tab file (không phải thẻ trong sidebar) — cùng dữ liệu agent đọc được
  trước khi sửa.
- **Banner lỗi index**: *Retry*, *View log*, *Ask agent* (attach log lỗi).

## Phím tắt dùng chung

| Phím | Ý nghĩa ở mọi module |
|---|---|
| `⌘↵` | Hành động chính của thực thể đang chọn (Send request, Try endpoint) |
| `⌘L` | Đưa thực thể đang chọn vào composer của agent |
| `⌘T` | Tạo task từ thực thể đang chọn |
| `⌘K` rồi `@` | Tìm symbol / thực thể xuyên module |
| `⌘⇧K` | Commit thay đổi đang chọn (file trong Code Graph, lượt trong Agent Hub) |

## Thứ tự triển khai gợi ý

1. `EntityRef` + `Shared / Entity Chip` + resolver cho `codegraph` (endpoint,
   planNode, file) — dùng ngay trong composer của Agent Hub (`agent.attach`).
2. ~~Intent registry; chuyển `openFileInProject` sang `codegraph.reveal`.~~ Xong.
3. API Client v1 với `api.fromEndpoint` (cần analyzer đọc `@RequestBody` /
   `@PathVariable` — xem [API Client § Phụ thuộc](/dev-kit/api-client#phụ-thuộc-analyzer-phải-hiểu-tham-số-của-handler)).
4. Tasks v1 — resolver `task` và `tasks.createFromPlan` cắm vào tab Plan.

Ba module mới thêm vào thứ tự đó như sau. Điểm đáng chú ý: **[Tài khoản](/dev-kit/accounts)
đi trước**, vì nó nhỏ nhất và hai module kia đều phải đợi nó, còn nếu làm sau
thì API Client và Git đều phải viết lại phần auth.

5. **Tài khoản v1** — record type `account`, provider registry với `github` +
   `generic`, verify, `Resolve` cho module khác. Chưa có module nào dùng thì nó
   vẫn có giá trị một mình: một danh sách "tôi đăng nhập gì, cái nào sắp hết hạn".
6. **`internal/gitparse`** — tách parser porcelain/diff ra leaf dùng chung.
   Thuần refactor, không đổi hành vi, và là thứ để `checkpoint` và `codegraph`
   thôi giữ hai bản.
7. **Git v1** — status + diff + stage/commit + branch, với `git.commitTurn` cắm
   vào Agent Hub ngay từ đầu (đó là lý do module này tồn tại). Push đến sau,
   cùng lúc với binding `git-remote` → account.
8. **API Client v1** — `api.fromEndpoint` + auth bằng account binding. Cần
   analyzer đọc tham số handler; xem bảng ba analyzer ở
   [API Client § Phụ thuộc](/dev-kit/api-client#phụ-thuộc-analyzer-phải-hiểu-tham-số-của-handler)
   — TypeScript gần sẵn sàng nhất, Lua thì không có gì để đọc.
